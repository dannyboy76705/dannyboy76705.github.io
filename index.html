CDCstore github repo
CDCstore in a nutshell takes a file or directory and chunks it to a specified chunk size. It then attaches a index that is used to access them later. The index can be mounted for transparent access, or cdcstore (add remove restore list verify) to manipulate the repo directly. On its own it has little value, but when paired with a sorter (such as my cdcsort) it makes a list of the most similar chunks together first. This list can then be passed to a compressor such as a tar.zst, tar.xz etc or Dwarfs for better compression. When used with my zfrag utility it magically mounts and only uses one FUSE call reducing system overhead. As you'll see I made all my tools to function on thier own, or integrate with my utilities I made to make my flow easier.

Debian buildcheck github repo
deb-buildcheck-suite is a collection of Debian focused utilites to aid in package creation. As of now there is configcheck, makecheck, and runcheck. Each utility uses Debian's offline ability to read the supplied package database and show what packages are required for each phase. If the package is not installed it will query what ones can fill the void. Initial Cmake and Meson were added Oct 29th 2026. Yes AI can do this, but it can't do it offline in a 100kb progam. This suite alone is the main reason I love Debian.

mjpegsuite repo
mjpegsuite is a toolset to take a YUV4MPEG stream (file or piped) and break it down to JPEG files for each frame. It does store aspect, colorspace etc. The main motivation for this was to deduplicate TV episodes with similar scenes to aid compression. when used with palscore frames are grouped together to aid compression. On a raw directory it can serve streams to via a pipe to another program, or it can mount a collection to a virtual drive so file.mkv can be served to editors that don't take stdin. zfrag has built-in support for virtual mounting so only one FUSE call is needed. There's less "knobs" to get good quailty frames out of JPEG and each file can be viewed in a image editer. This implentation controls the block restart codes to make data as similar as possible. Uncompressed repos will be bigger than other JPEG compressors, but will compress significantly better.

mkvgopsplit repo
mkvgopsplit is a simple progam with two jobs: split a mkv video file up at GOP boundaries, and reassebmle them at later times. It's main motivation was to chop a GOP segment for submission to whoever to show a bug, encoding flaw, etc. This is not practical for my original idea of deduplicating MPEG-2 streams as there's little redudancy in the data. What redudancy there is was killed by a frame offset here and there duing encodes.

sortof-suite repo
sortof-suite is a group of sorters that sort of sort data some way (yes a play on words). Each generate a list file suitible for tar.xz etc, Dwarfs, or zfrag. the main two is cdcsort and palscore. On video in paticular both work and give similar results but palscore is *much* faster as it incorporates a downscale to 32x32 before sorting. I've yet to find a video source where omiting this gave meaningfully better results.

zfrag repo
zfrag is a container I made that is mountable and seekable. It is cdcstore and mjpegstore aware. When used with them it will make two mount directories: a native and virtual. Native will be the actual files, while virtual will be the cdcstore file assembled files, or mjpegstore file.mkv's as one FUSE call handles both folders it alot less intense overhead wise on reads. It's very competive with Dwarfs when a sorted list is used as duplicates dont't take up much space. It can also be extracted with a regular tar.zst workflow. if streaming from it 1MB frames are reccomended while for cold storage all the way up to 32MB frames can be used.

zpaq-order repo
zpaq-order is a fork of the original zpaq code. The only modification is it has the ability to take TAR style sortlists as input.

zpaqfuse repo
zpaqfuse is a fuse mounter for zpaq archives. It's meant for use with the original zpaq in mind. zpaqfranz has this built into it now. This is here mainly if you dont want to install zpaqfranz or zpaq and you just want to mount a .zpaq archive. It is a *symmetrical* compressor so it is slow. It does save you having to do a full extraction though and that is the whole point.
